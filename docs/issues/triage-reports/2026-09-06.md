## Deliberated fixes

### shared-worktree-branch-race

- **Bug:** Concurrent Cursor agents on one machine can change a shared checkout's
  active branch between status checks and mutating git commands, causing result
  imports on the wrong branch.
- **Approach chosen:** Add `devops.git.branch_guard.assert_branch` and document
  worktree isolation guidance for agents.
- **Alternatives considered:** Platform-level branch locking (not available in
  this repo); mandatory integration into every git-mutating devops path (wider
  scope than the reported incident); marking not-reproducible (reproduction was
  confirmed in Cursor, just not in plain git sibling clones).
- **Tradeoffs:** Agents must call the guard explicitly before writes. Cursor can
  still change `HEAD` when the agent root moves; the guard only prevents
  accidental commits on the wrong branch.
- **Why not simpler:** Deletion is not applicable — the defect is real but
  partially outside repository control. A one-line doc-only change would not
  block the failure mode.
