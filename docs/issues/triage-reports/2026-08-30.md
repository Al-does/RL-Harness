## Deliberated fixes

### shared-worktree-branch-race

- **Bug:** Concurrent Cursor agents on one Mac can silently change which branch
  is checked out in a sibling clone when the agent root moves, so check-then-write
  git sequences (for example `git cherry-pick origin/results`) can target the
  wrong branch.
- **Approach chosen:** Add `devops/git_guard.py` (`uv run python -m devops.git_guard
  --expect <branch> -- <cmd>`) and document worktree isolation plus guard usage
  in `record-agent-issue` and `vast-provisioning` skills.
- **Alternatives considered:** (1) Close as not-a-harness-bug with docs only —
  rejected because agents need a concrete fail-fast hook before mutating git.
  (2) Fix in Cursor product — out of scope for this repo but still the true root
  cause. (3) Mandatory harness CLI integration — rejected as over-scoped; agents
  run ad-hoc git commands locally.
- **Tradeoffs:** The guard only protects wrapped commands; manual git without the
  wrapper remains vulnerable. Cursor may still switch branches between separate
  agent steps.
- **Why not simpler:** Documentation alone does not fail fast; a one-file helper
  with tests is the smallest executable mitigation.
