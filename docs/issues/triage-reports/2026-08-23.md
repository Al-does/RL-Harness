## Deliberated fixes

### shared-worktree-branch-race

- **Bug:** Concurrent Cursor agents sharing one macOS worktree can silently
  change `HEAD`, so cherry-pick/commit/push land on the wrong branch. Moving the
  agent root between sibling clones can also check out the experiment branch in
  the harness clone.
- **Approach chosen:** Add `assert_branch()` and a small CLI so agents fail
  fast immediately before mutating Git operations when `HEAD` drifted.
- **Alternatives considered:** (1) Document-only guidance for separate
  worktrees per agent — does not prevent mistakes at mutation time. (2) Harness
  runtime branch locking — violates ownership rules (issue state must not live
  in harness runtime/CLI). (3) Mark not-reproducible — rejected; July macOS
  reproduction evidence is credible even though the cloud triage VM cannot replay
  Cursor root-move behavior.
- **Tradeoffs:** Mitigation requires agents to call the guard before each git
  write; it does not stop concurrent sessions from changing branches between
  check and write without additional locking.
- **Why not simpler:** Deletion or narrowing of existing code does not address
  the external orchestration race; the smallest behavioral addition is an
  explicit pre-mutation assertion.
